# Spec Delta

## Purpose

Позволяет запустить сервис на новой машине без ручного редактирования файлов: конфигурация создаётся мастером, проверяется до сохранения и может быть задана неинтерактивно в контейнере.

## ADDED Requirements

### Requirement: Проверка наличия конфигурации при старте

Сервис SHALL при запуске проверять наличие и валидность конфигурационного файла и SHALL запускать мастер настройки, если файл отсутствует или не проходит валидацию.

#### Scenario: Конфигурация существует и валидна

- **WHEN** сервис запускается и находит валидный конфигурационный файл
- **THEN** мастер не запускается, сервис переходит к работе

#### Scenario: Конфигурации нет

- **WHEN** сервис запускается, а конфигурационного файла нет
- **THEN** запускается интерактивный мастер настройки

#### Scenario: Конфигурация повреждена

- **WHEN** файл конфигурации существует, но не соответствует схеме
- **THEN** сервис сообщает об ошибке с указанием проблемы и не начинает вещание с частично прочитанными настройками

### Requirement: Интерактивный мастер настройки

Мастер SHALL запрашивать токен Foreca и локацию, SHALL проверять введённые данные запросом к Foreca до сохранения и SHALL записывать конфигурацию только после успешной проверки. После успешного сохранения сервис SHALL сразу начинать вещание, не требуя повторного запуска.

#### Scenario: Успешная настройка

- **WHEN** пользователь вводит действующий токен и существующую локацию
- **THEN** мастер сохраняет конфигурацию и запускает вещание в рамках того же запуска

#### Scenario: Неверный токен

- **WHEN** пользователь вводит токен, на который Foreca отвечает ошибкой авторизации
- **THEN** мастер сообщает об ошибке и предлагает ввести токен повторно, не сохраняя конфигурацию

#### Scenario: Локация не найдена

- **WHEN** введённая локация не находится поиском Foreca
- **THEN** мастер показывает это и предлагает ввести локацию повторно, не сохраняя конфигурацию

#### Scenario: Локация найдена неоднозначно

- **WHEN** поиск по введённому названию возвращает несколько различных вариантов
- **THEN** мастер показывает найденные варианты с регионом и страной и требует выбрать один до сохранения

### Requirement: Защита токена

Сервис SHALL записывать конфигурацию с правами доступа только для владельца и SHALL не выводить токен в журнал, консоль мастера или сообщения об ошибках. Токен SHALL проверяться на допустимые символы до отправки запроса: он попадает в HTTP-заголовок, поэтому недопустимые символы должны отвергаться с понятным сообщением, а не выглядеть как сетевая ошибка.

#### Scenario: Права на файл конфигурации

- **WHEN** мастер сохраняет конфигурацию
- **THEN** файл получает права, запрещающие чтение другим пользователям

#### Scenario: Токен содержит недопустимые символы

- **WHEN** введённый токен содержит символы, недопустимые в HTTP-заголовке
- **THEN** сервис сообщает о недопустимых символах и предлагает ввести токен повторно, не выполняя запрос

#### Scenario: Ответ не удалось разобрать

- **WHEN** проверка токена завершилась ошибкой разбора ответа
- **THEN** сервис сообщает, что это дефект сервиса, а не проблема токена или сети

#### Scenario: Токен не попадает в журнал

- **WHEN** сервис пишет журнал об ошибке запроса к Foreca
- **THEN** в записи отсутствует полное значение токена

#### Scenario: Конфигурация не попадает в репозиторий

- **WHEN** разработчик добавляет файлы проекта в систему контроля версий
- **THEN** файл с реальной конфигурацией исключён, а в репозитории присутствует только пример без секретов

### Requirement: Атомарная запись конфигурации

Сервис SHALL записывать конфигурацию через временный файл с последующим переименованием, чтобы прерванная запись не оставляла частично записанный файл.

#### Scenario: Запись прервана

- **WHEN** процесс завершается во время сохранения конфигурации
- **THEN** предыдущая валидная конфигурация остаётся неизменной, а временный файл не воспринимается как конфигурация

### Requirement: Неинтерактивный режим

Сервис SHALL поддерживать запуск без интерактивного ввода, принимая параметры через аргументы командной строки или переменные окружения, и SHALL завершаться с понятной ошибкой, если конфигурация отсутствует и ввод невозможен.

#### Scenario: Конфигурация задана переменными окружения

- **WHEN** сервис запущен в контейнере без терминала с заданными токеном и локацией
- **THEN** сервис не запускает мастер и начинает работу с указанными параметрами

#### Scenario: Нет терминала и нет конфигурации

- **WHEN** сервис запущен без терминала, без конфигурационного файла и без параметров окружения
- **THEN** сервис завершается с ненулевым кодом и сообщением, какие параметры требуется задать, вместо ожидания ввода

### Requirement: Повторная настройка

Сервис SHALL поддерживать явный запуск мастера для изменения локации или токена без ручного удаления конфигурации.

#### Scenario: Пользователь меняет локацию

- **WHEN** сервис запущен с флагом повторной настройки
- **THEN** мастер запускается заново и после успешной проверки заменяет значения в конфигурации

### Requirement: Состав конфигурации

Конфигурация SHALL содержать токен Foreca, локацию и её координаты, параметры обновления прогноза, параметры видеопотока и адрес RTSP-публикации, а также каталог для кэша.

#### Scenario: Значения по умолчанию

- **WHEN** мастер сохраняет конфигурацию
- **THEN** в ней присутствуют значения по умолчанию для интервала обновления, частоты кадров, битрейта и каталога кэша, которые пользователю не требуется вводить вручную

#### Scenario: Изменение параметров потока

- **WHEN** пользователь меняет частоту кадров или битрейт в конфигурации
- **THEN** сервис применяет новые значения при следующем запуске без изменения кода
