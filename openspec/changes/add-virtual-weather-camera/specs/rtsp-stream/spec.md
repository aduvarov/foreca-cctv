# Spec Delta

## Purpose

Отдаёт видеорегистратору непрерывный RTSP-поток с кадром прогноза и сохраняет вещание при сбоях сети, падении кодировщика и отсутствии данных.

## ADDED Requirements

### Requirement: Публикация потока в RTSP-сервер

Сервис SHALL публиковать кадры в RTSP-сервер по адресу из конфигурации, используя FFmpeg с кодировщиком H.264 и транспортом RTSP/TCP.

#### Scenario: Публикация установлена

- **WHEN** сервис запущен и RTSP-сервер доступен
- **THEN** FFmpeg публикует поток на настроенный путь, а сервис сообщает о переходе потока в состояние «в эфире»

#### Scenario: RTSP-сервер недоступен при старте

- **WHEN** при старте RTSP-сервер недоступен
- **THEN** публикация повторяется с задержкой, а сервис не завершается и продолжает попытки

### Requirement: Параметры видеопотока

Поток SHALL быть H.264 с профилем Main, уровнем не выше 3.1, пиксельным форматом yuv420p, без звуковой дорожки, с постоянным битрейтом и ключевым кадром на каждом кадре.

#### Scenario: Совместимость с аппаратным регистратором

- **WHEN** регистратор подключается к потоку
- **THEN** поток объявляет H.264 Main, 640x480, yuv420p, одну видеодорожку

#### Scenario: Подключение в произвольный момент

- **WHEN** регистратор подключается к уже идущему потоку
- **THEN** служебные заголовки H.264 повторяются с каждым ключевым кадром, поэтому изображение появляется без ожидания следующего ключевого кадра

### Requirement: Две ссылки на один поток

Сервис SHALL предоставлять две точки подключения к одному и тому же видеопотоку без второго кодирования и без второго процесса кодировщика.

#### Scenario: Обе ссылки отдают одинаковый поток

- **WHEN** два читателя подключаются к основной и дополнительной ссылке
- **THEN** оба получают один и тот же поток с одинаковыми параметрами кодирования

#### Scenario: Одна ссылка недоступна

- **WHEN** читатель подключается к дополнительной ссылке при работающей основной
- **THEN** подключение успешно, потому что дополнительная ссылка разрешается в основную

### Requirement: Непрерывность при обновлении данных

Сервис SHALL обновлять содержимое кадра без остановки кодировщика и без разрыва потока при получении новых данных прогноза.

#### Scenario: Пришли новые данные

- **WHEN** получен новый успешный прогноз
- **THEN** следующий публикуемый кадр содержит новые данные, а читатели не отключаются и не наблюдают перезапуск потока

#### Scenario: Читатель подключён во время обновления

- **WHEN** читатель непрерывно читает поток в момент смены данных
- **THEN** чтение не прерывается и не сообщает об изменении параметров видеопотока

### Requirement: Offline-заглушка

RTSP-сервер SHALL быть настроен так, чтобы при отсутствии публикации путь отдавал заранее подготовленную offline-заглушку с параметрами, совпадающими с живым потоком.

#### Scenario: Нет публикации

- **WHEN** публикация отсутствует
- **THEN** читатель получает заглушку с теми же разрешением, профилем и форматом пикселей, что и живой поток, а не ошибку «поток не найден»

#### Scenario: Заглушка не попадает в архив

- **WHEN** регистратор пишет поток в архив во время показа заглушки
- **THEN** заглушка помечена так, чтобы не записываться как содержимое канала

### Requirement: Восстановление кодировщика

Сервис SHALL обнаруживать завершение процесса кодировщика и перезапускать его с задержкой, сохраняя текущие данные прогноза.

#### Scenario: Кодировщик завершился с ошибкой

- **WHEN** процесс FFmpeg завершился с ненулевым кодом
- **THEN** сервис перезапускает его с экспоненциально растущей задержкой и после восстановления продолжает публиковать тот же прогноз

#### Scenario: Повторные падения подряд

- **WHEN** кодировщик падает несколько раз подряд
- **THEN** задержка между перезапусками растёт до настроенного предела, а сервис продолжает попытки и не завершается

### Requirement: Отсутствие временных файлов на кадр

Сервис SHALL передавать кадры кодировщику через стандартный ввод процесса и SHALL не создавать временные файлы на каждый кадр.

#### Scenario: Кадр передаётся через поток

- **WHEN** сервис публикует очередной кадр
- **THEN** кадр передаётся в стандартный ввод FFmpeg без записи промежуточного файла на диск

### Requirement: Устойчивость процесса к отсутствию данных

Сервис SHALL продолжать публикацию кадров при отсутствии прогноза, показывая кадр с сообщением об отсутствии данных.

#### Scenario: Данных нет, публикация идёт

- **WHEN** прогноз недоступен, но процесс кодировщика работает
- **THEN** сервис продолжает публиковать кадры с сообщением об отсутствии данных и логотипом Foreca

### Requirement: Наблюдаемость состояния потока

Сервис SHALL предоставлять состояние вещания, включающее признак активной публикации, время последнего успешного кадра и число перезапусков кодировщика.

#### Scenario: Состояние доступно для проверки

- **WHEN** сервис работает
- **THEN** состояние вещания можно получить локально и использовать для проверки работоспособности
